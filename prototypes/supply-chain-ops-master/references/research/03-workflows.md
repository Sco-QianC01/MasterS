### 工作流 1 — 跑一轮月度 S&OP / IBP

S&OP（Sales and Operations Planning，产销协同计划）是把销售想卖的、工厂能做的、财务能承受的三张数字拧成一张的月度循环。ASCM/APICS 把它定义为「在战术层面平衡需求与供应、并把运营计划与业务计划连起来」的流程；IBP（Integrated Business Planning，集成业务计划）是它的加长版——把财务、产品、资本开支和 18-24 个月的长视角也拉进来。[T03-S001] [T03-S002]

#### 1.1 入门 SOP

1. **产品评审（Product Review）** —— 谁做：产品经理 / PLM 负责人主持，研发与市场参加。输入：新品上市计划与 NPI 门径状态、退市（EOL）清单、替代关系表。产出：一份「未来 12-24 个月产品组合变更清单」，写清每个新品的上市月份、爬坡曲线、替代掉谁。小公司常把这步并进需求评审。
2. **需求评审（Demand Review）** —— 谁做：需求计划经理主持，销售、市场、大客户经理参加。输入：统计基线预测、销售管道、促销日历、大客户滚动预测、产品评审输出。产出：**不受产能约束的共识需求计划**（unconstrained demand plan），按产品族、按月、覆盖滚动 18-24 个月。这一步的铁律是不许先自我审查产能。
3. **供应评审（Supply Review）** —— 谁做：供应计划 / 主计划经理主持，工厂、采购、物流参加。输入：共识需求计划、产能日历（人 / 机 / 模具）、长交期件供货能力、现有库存与在途、供应商产能承诺。产出：粗能力计划（RCCP，Rough-Cut Capacity Planning）结果 + **供需缺口清单**——哪个族、哪个月、缺多少，以及补救方案 A/B/C 及各自的成本、交期、风险。
4. **财务协调（Financial Reconciliation）** —— 谁做：FP&A。输入：需求计划 × 价格 = 收入预测；供应计划 × 成本 = 成本与库存预测。产出：本轮计划的损益与现金 / 库存影响，以及与年度经营计划（AOP）的差距（gap to plan）。
5. **预 S&OP（Pre-S&OP，协调会）** —— 谁做：供应链计划总监主持，各职能中层。输入：以上四项。产出：(a) 中层能拍板的直接结案；(b) 结不了的做成 3-5 个**决策包**，每包写清议题、方案选项、每个选项的量 / 钱 / 服务水平后果、建议方案、需要谁签字。
6. **执行 S&OP（Executive S&OP）** —— 谁做：总经理 / CEO 主持，销售、运营、财务、研发一把手到场。输入：决策包 + 一页仪表盘（上月计划 vs 实际、预测准确率、准时足量交付 OTIF、库存周转、缺口的损益影响）。产出：**签字的单一数字计划**（one-number plan）+ 决议记录（谁、做什么、何时前完成）。
7. **发布与落地** —— 谁做：计划部门。输入：签字后的计划。产出：更新后的主生产计划 MPS、给工厂的产能承诺、给采购的物料需求、给销售的可售量。业内常见做法是会后 48-72 小时内发布（业内估计，非标准规定）。

#### 1.2 资深路径

- **跳过**：老手不再逐族逐月过一遍。只过例外——与上月计划偏差超门槛（常见设 ±10%，业内估计）、或缺口大于若干天供货量、或有明确决策需求的族；其余默认通过。产品评审若无重大变更，直接并入需求评审。仪表盘上「绿色」的部分一句话带过。
- **优化**：把会议从「汇报现状」改成「只做决策」——材料会前 48 小时预读，会上只讨论分歧。把「共识」落到实处：争议必须落成两个具体数字加各自的假设，而不是折中。用情景（base / upside / downside）代替单点数字，让高层决策的是**触发条件**（"如果订单到 X，就启动第二班"）而不是一个数。
- **额外**：老手额外做四件新手不做的事——(a) **假设登记表**（assumption log）：每个预测背后的假设写下来，下月复盘假设对错而不是数字对错；(b) **决议追踪**：上月决议的按期完成率，是 S&OP 成熟度比任何准确率都靠谱的指标；(c) **长周期视角**：把 18-24 个月的产能扩张 / 资本开支触发点挂进会议，这正是 IBP 与传统 S&OP 的实质差别；(d) **用 FVA（见工作流 2）终结口水战**：拿数据证明销售的手工调整到底加分还是减分，而不是靠嗓门。

#### 1.3 失败模式自检

| 崩在哪一步 | 早期判别信号 | 处置 |
|---|---|---|
| 需求评审产出的是「被产能修剪过的预测」 | 需求总量恰好等于产能；每个月都刚好可满足 | 需求评审只出无约束数字，约束到供应评审才引入 |
| 预 S&OP 变成第二场汇报会 | 会议纪要里找不到「选项 A/B + 建议」 | 强制决策包模板，没有选项不许上会 |
| 执行 S&OP 退化成月度经营分析会 | 议程里回顾过去的时间占比 > 40% | 把回顾压到 10 分钟，其余谈未来 3-18 个月 |
| 销售报高、生产报低 | 某销售的 bias（带符号偏差）连续 3 期同向 | 这是行为问题不是模型问题：把 bias 而非绝对精度纳入 KPI，并把产能分配规则前置公开 |
| 计划签了字工厂不执行 | MPS 汇总量 ≠ S&OP 家族量（差 >5% 即脱节，业内估计） | 建立家族计划到 MPS 的强制对账 |
| 只有供应链一个部门在开会 | 财务 / 销售一把手连续两次派代表 | 这是 S&OP 死亡的第一征兆，需要 CEO 出面而不是流程优化 |

#### 1.4 近期变化（2024-2026）

- **「攒齐数据再开会」正在退场**。SAP IBP、Kinaxis Maestro（原 RapidResponse）、o9、Blue Yonder 都在推持续 / 滚动的 S&OP 与情景对比：会前跑 3 个情景，会上比结果。Kinaxis 的核心主张就是并发式（concurrent）重算而非顺序式串行传递。[T03-S003] [T03-S004]
- **生成式 AI 落在会议材料层，不在决策层**。2024-2025 各家上线的 copilot，最稳的用法是「偏差自动叙述」（把上月计划 vs 实际的差异写成人话）和「情景自然语言问答」，让 AI 直接定计划的案例仍属试点。[T03-S003] [T03-S004]
- **断链之后重点从「平衡供需」移向「情景与风险」**。2020-2023 的断供、2024 年红海绕行、关税波动，让很多公司在 IBP 议程里专门加一段供应风险评审（双源比例、关税情景、单点故障清单）。
- `(Decay risk: medium)` —— 流程骨架（需求 → 供应 → 预 → 执行）二十年没变，属低衰减；工具层与 AI / 情景部分变化快。

### 工作流 2 — 需求预测与预测误差复盘（含 FVA 预测增值分析）

#### 2.1 入门 SOP

1. **定颗粒度与周期** —— 谁做：需求计划员。输入：这份预测要驱动什么决策（补货？产能？长交期件采购？）。产出：预测层级（SKU-地点-周 / 产品族-月）+ 冻结与滚动规则。原则：为决策预测，不为好看预测。
2. **清洗历史，把「出货」还原成「需求」** —— 谁做：需求计划员。输入：24-36 个月出货 / 订单历史。产出：**需求历史**——补回缺货造成的损失量、剔除一次性大单与内部转仓、标注促销期。这一步不做，后面全是垃圾。
3. **分层：ABC-XYZ 九宫格** —— 谁做：需求计划员。输入：年销售额或毛利（ABC 维度）+ 需求变异系数 CV（XYZ 维度，CV = 标准差 / 均值）。产出：九个格子，每格配不同的预测方法与人工投入强度。AX（金额大、需求稳）用统计模型加少量人工；CZ（金额小、需求乱）不投人工，交给简单方法或纯补货规则。常见分界是 CV<0.5 为 X、0.5-1.0 为 Y、>1.0 为 Z（业内常用经验值，非标准，各家门槛不同）。[T03-S005]
4. **选模型跑统计基线** —— 谁做：需求计划员 / 数据分析。产出：statistical baseline forecast。间歇性需求（大量期为 0）用 Croston / SBA / TSB 类方法，不要用移动平均；有趋势 + 季节用 ETS / Holt-Winters / ARIMA；有促销与价格因素用带外生变量的回归或机器学习。[T03-S006]
5. **收集情报、做人工调整（必须留痕）** —— 谁做：销售、市场、需求计划。产出：**带记录的调整**——谁调的、调了多少、依据什么事件。系统里必须同时保留「统计预测」和「最终预测」两列，否则第 7 步的 FVA 做不出来。
6. **共识与发布** —— 进入工作流 1 的需求评审。
7. **误差复盘** —— 谁做：需求计划经理。输入：锁定 lag 的历史预测（例如 lag-1 / lag-3，即提前 1 / 3 期发出的那一版）与实际值。产出：MAPE / WMAPE / bias 报表 + FVA 阶梯。

**误差指标怎么算、怎么读：**

- `MAPE = mean(|A−F| / A)`。坑：分母是实际值，实际值小的时候单点误差被放大到几百 %，实际为 0 时无定义。因此 SKU 层几乎不能用 MAPE 做汇总。[T03-S006]
- `WMAPE = Σ|A−F| / ΣA`（也写作 MAD/Mean ratio）。按量加权、抗小分母，是 SKU 汇总的默认选择。
- `bias = Σ(F−A) / ΣA`，**带符号**。准确率不差但 bias 长期单边，说明是系统性高报 / 低报——流程与行为问题，不是模型问题。
- 关键认知：**误差没有绝对的好坏门槛**。同样 30% 的 WMAPE，在快消是灾难，在工业备件可能已经很好。唯一有意义的读法是和 naive 基准比——这就是 FVA。

**FVA（Forecast Value Added，预测增值）怎么做：**

1. 画出预测流程的阶梯：`naive 基准 → 统计模型 → 需求计划员调整 → 销售 / 管理层调整 → 最终共识预测`。naive 通常取上期实际（random walk）或季节性 naive。
2. 对同一批 SKU、同一个 lag、同一段时间，逐级计算误差（用 WMAPE 或 MAE）。
3. `FVA = 上一级的误差 − 本级的误差`。正数表示这一步加分，负数表示这一步在破坏预测。
4. 读法与动作：如果「销售调整」这一级 FVA 持续为负，就该取消这一步，或改成只在有明确事件依据时才允许调整。FVA 这套方法由 Michael Gilliland 在 SAS 期间系统化并推广，SAS 的白皮书《Forecast Value Added Analysis: Step by Step》是常被引用的原始出处；2024 年 *International Journal of Forecasting* 上的 "Forecast value added in demand planning" 给了它正式的学术处理。[T03-S007] [T03-S008]
5. 常被引用的震撼数字：有研究发现相当比例（Gilliland 引述的一项研究中约 52%）的企业预测比随机游走还差——用它来说服团队先建 naive 基准，但引用时要标出处，因为这个比例随样本变化。[T03-S007] [T03-S009]

#### 2.2 资深路径

- **跳过**：老手跳过「给每个 SKU 都人工调一遍」。CZ 格子（低值、高变异）根本不投人工，用简单方法加库存策略兜住。也跳过「让 MAPE 数字好看」的游戏——不再逐 SKU 汇报 MAPE。
- **优化**：把误差报表从「按 SKU 误差排序」优化成「按误差造成的钱 / 库存后果排序」（误差 × 单价 × 是否长交期）；把 lag 固定死（永远比 lag-3，不比 lag-0），否则各部门报的准确率根本不可比；用滚动回测（rolling-origin backtest）选模型，而不是拿整段历史的拟合优度选。
- **额外**：老手额外做——(a) 建 FVA 阶梯并**据此砍掉不增值的环节**，这是这条流程里杠杆最大的动作；(b) 出**概率预测**（分位数）而不是点预测，直接喂给安全库存与服务水平决策；(c) 把预测误差与库存参数打通——误差变了安全库存跟着变，而不是一年调一次；(d) 大偏差做归因四分类：模型错 / 事件未知 / 事件知道但没输进系统 / 人为乱调，只有第四类才需要治人；(e) 新模型走「冠军-挑战者」：影子跑 3 个周期再上线。

#### 2.3 失败模式自检

- **崩点 1（最常见）**：拿出货数据当需求数据。判别：缺货月份的「需求」莫名其妙低；新品上市初期数据被产能限制压平。
- **崩点 2**：口径漂移。同一个「预测准确率」，A 部门算 1−MAPE、B 部门算 1−WMAPE、C 部门用 lag-0。判别：两个部门报的数差 10 个点以上。先定义，再讨论。
- **崩点 3**：没有 naive 基准。团队在没有参照系的情况下互相攻击，谁嗓门大谁赢。
- **崩点 4**：人工调整没留痕，FVA 做不出来。判别：系统里只有一个最终数字。
- **崩点 5**：新品与促销硬套统计模型。新品没有历史，正解是类比品（analogous item）+ 上市曲线，这不是模型能力问题。
- **崩点 6**：误差指标好转，但缺货和库存没好转——说明在优化一个和业务不挂钩的指标。

#### 2.4 近期变化（2024-2026）

- **机器学习全局模型进入主流选项**。M5 竞赛之后，梯度提升（LightGBM 类）与 N-BEATS / NHITS / TFT 这类深度模型在多 SKU 场景被反复验证可稳定超过逐序列统计法；但 2024-2026 的实务共识仍是先把数据清洗与分层做对再谈模型，且统计基线必须作为对照组保留。[T03-S006] [T03-S010]
- **时间序列基础模型（foundation models）进入试点**：TimeGPT、Amazon Chronos、Lag-Llama、Salesforce Moirai 等 2023-2025 陆续发布，零样本（zero-shot）预测的价值集中在「新品 / 短历史」和「快速起步」；在历史充足的成熟 SKU 上尚未稳定压过调好的传统方法。[T03-S011]
- **概率预测取代点预测**成为高级用法，因为分位数能直接驱动库存与服务水平决策，不需要再经过一层安全库存近似公式。
- `(Decay risk: high)` —— 模型与工具这一层 12-18 个月换一轮。但 FVA、WMAPE/bias、数据清洗、ABC-XYZ 分层这些流程骨架是低衰减的。

### 工作流 3 — 设定库存分级与安全库存

#### 3.1 入门 SOP

1. **先把「服务水平」的口径定死** —— 谁做：供应链总监 + 销售。输入：客户合同、行业惯例。产出：明确区分 **cycle service level（CSL，一个补货周期内不缺货的概率）** 与 **fill rate（β，按数量的满足率）**。这两个不是一回事：CSL 95% 对应的 fill rate 通常高于 95%。很多公司混着用，导致目标从一开始就定错。
2. **ABC 分类（金额维度）** —— 谁做：计划员。输入：过去 12 个月年用量 × 单价（或毛利）。产出：A/B/C 三档。常见切分是金额累计 80% / 15% / 5%（帕累托，业内常用经验值，非标准）。
3. **XYZ 分类（变异维度）** —— 谁做：计划员。输入：月度或周度需求序列。产出：按变异系数 `CV = σ/μ` 分档。常见门槛之一是 X: CV<0.5、Y: 0.5–1.0、Z: >1.0；另一套常见门槛是 X≤0.2、Y 0.2–0.5、Z≥0.5。**没有统一标准，各家按自己的数据分布调**。[T03-S005] 间歇性需求（大量期为 0）应单列一类，不适用 CV。
4. **合成九宫格 → 策略矩阵** —— 产出：每格一套库存策略。AX（金额大、需求稳）：高服务水平 + 低安全库存，靠预测准和高频补货；AZ（金额大、需求乱）：高服务水平但只能靠高安全库存，是成本痛点，优先做需求整形或缩短交期；CX：定量补货 / 看板，不投人工；CZ：认真考虑不备货、按单采购，甚至砍掉。
5. **逐格设服务水平目标** —— 不要全公司一刀切 95%。产出：目标 CSL 表。
6. **算安全库存** —— 谁做：计划员。
   - 只考虑需求变异：`SS = z × σ_D × √L`
   - 需求与交期都变异：`SS = z × √( L̄·σ_D² + D̄²·σ_L² )` [T03-S012] [T03-S013]
   - 常用 z 值（标准正态分位数）：90% → 1.28；95% → 1.65；97.5% → 1.96；98% → 2.05；99% → 2.33；99.9% → 3.09
   - **铁律**：`σ_D` 的时间单位必须与 `L` 一致（都按周或都按月），否则结果差几倍。
7. **算触发点** —— 连续盘点制：`ROP = D̄ × L̄ + SS`；周期盘点制（每 R 天复核一次）：目标水位 `= D̄ × (L̄ + R) + SS`。
8. **落进系统并定复核节奏** —— 产出：ERP/APS 参数（安全库存、ROP、批量、MOQ）+ 复核周期。常见做法是 A 类月度、B 类季度、C 类半年复核（业内常用做法，非标准）。
9. **事后校验** —— 产出：实际服务水平 vs 目标、库存周转 vs 目标、缺货件的根因清单。

**「拍脑袋」和「按公式」的差距到底在哪：**

- 拍脑袋的典型做法是「安全库存 = 统一 N 天用量」（比如全公司 30 天）。它隐含假设「波动大小与平均需求成正比」。对 X 类是纯浪费（稳定品被压了不必要的库存），对 Z 类是根本不够（乱品的尖峰 30 天挡不住）。
- 公式给出的第一个洞察：**安全库存与交期的平方根成正比，不是与交期成正比**。交期从 4 周砍到 1 周，安全库存降到原来的 1/2（√4 = 2），不是 1/4。老手用这个「平方根规律」来回答"缩短交期到底值多少钱"。
- 第二个洞察：把交期变异 `σ_L` 算进去后，很多进口件的安全库存**主导项是 `D̄²·σ_L²` 而不是 `L̄·σ_D²`**。翻译成人话：稳住供应商的交期，比把预测做得更准更值钱。这个结论拍脑袋绝对看不出来。
- 第三个洞察（谈判弹药）：服务水平从 95%（z=1.65）提到 99%（z=2.33），安全库存涨约 41%；从 99% 再提到 99.9%（z=3.09），再涨约 33%。尾部很贵——拿这个和销售谈"你到底要多少服务水平"。

#### 3.2 资深路径

- **跳过**：老手跳过对 C 类件做精细公式计算，直接给「几个月用量」或上看板；也跳过为每个 SKU 单独设服务水平——按格子设，不按件设。
- **优化**：把公式里的 `σ` 从「历史需求标准差」优化成「**预测误差标准差**」——这是更正确的做法，因为安全库存挡的是预测误差，不是需求波动本身（有强季节性时两者差很远）。再把「逐 SKU 定 z」优化成「在总库存预算约束下分配服务水平」，即让边际库存成本等于边际缺货成本。
- **额外**：老手额外做——(a) **MEIO 多级库存优化**：不在每一级都放安全库存，而是算出把库存放在哪一级最省；(b) 把 `σ_L` 单独跟踪并作为供应商 KPI 推动改善，而不是被动地用更多库存去吸收；(c) **季节性动态安全库存**（旺季前抬、淡季降），不是全年一个数；(d) 把安全库存参数变更纳入审批与留痕，防止"谁都能改一改"；(e) 评估 **DDMRP** 的解耦点 + 缓冲区做法作为整套替代方案。[T03-S014]

#### 3.3 失败模式自检

- **崩点 1**：`σ_D` 与 `L` 时间单位不一致。判别：算出来的安全库存大得离谱或小得离谱（差 2-5 倍）。
- **崩点 2**：用历史需求标准差而非预测误差标准差，且需求有强趋势 / 季节。判别：季节性强的品安全库存异常高——σ 被季节性撑大了。
- **崩点 3**：套用正态分布 z 公式，但实际需求是间歇性 / 长尾。判别：实际服务水平系统性低于目标。→ 改用经验分布或直接用分位数预测。
- **崩点 4**：参数设好后从不复核。判别：安全库存字段的最后修改日期超过 12 个月。
- **崩点 5**：把安全库存当成「不许动的死库存」。它本应平均被消耗掉一半左右。判别：安全库存几乎从不被触及（设高了），或经常见底（设低了）。
- **崩点 6**：服务水平目标定在 99%+，但没有人算过这个 0.9 个百分点要多少钱。

#### 3.4 近期变化（2024-2026）

- **MEIO 从高端 APS 的专属功能下沉**：SAP IBP、Kinaxis、o9、Blue Yonder 都有库存优化模块，中型企业开始用得起。[T03-S004] [T03-S003]（vendor docs）
- **DDMRP 持续扩散**：Demand Driven Institute 的五大组件（战略库存定位 / 缓冲profile 与水位 / 动态调整 / 需求驱动计划 / 可视化协同执行）在离散制造被越来越多采用；Microsoft Dynamics 365 SCM 已内置 DDMRP 支持。它的主张是不要在每个件上放安全库存，而是选战略解耦点放缓冲，用净流量方程驱动补货。[T03-S014] [T03-S015]
- **交期变异被写进合同**：2022-2024 断链之后，很多企业把「交期准时率」和交期波动本身列入供应商 KPI，而不再只是用库存被动吸收。
- **概率预测直接输出分位数**，跳过 z 公式这一层近似（见工作流 2）。
- `(Decay risk: low)` —— 安全库存公式、ABC-XYZ、平方根规律是几十年不变的东西；变的只是工具可得性。

### 工作流 4 — MRP 跑批与例外消息处理

#### 4.1 入门 SOP

1. **跑批前查数据** —— 谁做：计划员。输入：BOM 准确率、库存准确率、交期与批量参数、开口订单状态。产出：跑批前检查清单。铁律：**MRP 不产生信息，它只放大你已有的错误**——BOM 错一个件，多级展开后错一片。
2. **确认主生产计划 MPS** —— 谁做：主计划员。输入：S&OP 家族计划、客户订单、预测（按消耗规则扣减）。产出：成品级 MPS，且已通过粗能力校验 RCCP。
3. **跑 MRP 展开** —— 系统按 low-level code 逐层往下：
   - 毛需求 = 上层计划订单 × 单位用量 × (1 + 损耗率)
   - 净需求 = 毛需求 − 现有库存 − 在途 − 已分配 + 安全库存
   - 按批量规则成型为计划订单：L4L（按需批量）/ 固定批量 / MOQ 最小起订量 / 倍数 / POQ 期间订货量
   - 按交期倒推下达日期（lead time offsetting）
4. **处理例外消息（action messages）** —— 谁做：计划员。典型类型：
   - `Reschedule In`（提前）：已下订单到料日晚于需求日 → 催料
   - `Reschedule Out`（推迟）：到料早于需求 → 推迟，避免早到库存与占用现金
   - `Cancel`（取消）：需求消失
   - `Release`（下达）：计划订单到了下达时点
   - `Past Due`（已过期）：需求日已经在过去——这类消息堆积是系统失控的最早信号
5. **排序与过滤** —— 产出：只处理影响成品交付的例外。过滤规则三层：先按天数容差过滤（例如偏差 <3 天的推迟消息不看，业内常见做法）；再按物料价值 / 关键度排序；最后按是否影响已承诺的客户交期。
6. **齐套检查与缺料清单** —— 谁做：计划员 + 生管。输入：工单 BOM vs 可用库存（必须多级，不能只查第一层）。产出：齐套率报表 + 缺料清单（短什么、短多少、预计到料、影响哪些工单和客户订单）。
7. **下达与闭环** —— 计划员 → 采购 / 生产。产出：采购申请 / 采购订单、生产工单；反馈闭环：供应商确认交期必须回写系统，否则下一轮跑批仍按错误交期算。

**MRP nervousness（计划神经质）怎么产生、怎么抑制：**

产生机制：MRP 是确定性重算——每次跑批都从当前状态重新算一遍。上层一个小变动（预测微调、一张订单改期、一次盘点差异），经过多级 BOM 展开与批量规则的非线性放大，在下层会变成大量改期 / 取消 / 新增消息。**批量规则的跳变是主要放大器**：上层需求少 1 个，可能导致某层少凑一个批量，进而下层整批订单消失。在多级生产环境中，一层的数量或时间改动会连锁引发其他层的改动，这正是文献所定义的 nervousness。[T03-S016] [T03-S018]

抑制手段（按学术与实务证据的有效性排序）：

1. **冻结主生产计划的前段**。这是研究里最一致的结论：冻结区长度覆盖**累积提前期（cumulative lead time）**时稳定性收益最大；冻结比例越高越稳定，但对需求变化的响应越差——这是稳定性与成本 / 服务的显式权衡。[T03-S018] [T03-S019]
2. **时界（time fence）**：需求时界 DTF（demand time fence，界内只认实际订单不认预测）+ 计划时界 PTF（planning time fence，界内系统不自动新建或改期计划订单，只给人提示）。
3. **批量规则的选择**：固定周期 / 固定批量比 L4L 稳定（L4L 把需求变化 1:1 传下去），代价是库存上升；常见折中是上层用固定周期、低层用 L4L。有专门的抑制型批量算法文献。[T03-S017] [T03-S019]
4. **例外消息容差**：设定"多少天以内的偏差不提示"。
5. **成品级安全库存**（而不是每层都放），用来吸收上层波动。
6. **净变式（net change）与全重生成（regenerative）的取舍**：净变式减少无谓翻搅，但也会把小改动更快地传播下去。

反直觉的一点：加安全库存能减少神经质，但代价是库存；**只有缩短交期同时减少神经质和库存**——所以缩短交期是唯一的双赢抑制手段。

#### 4.2 资深路径

- **跳过**：老手跳过 90% 的例外消息。不看推迟消息（除非影响仓容或现金）、不看小额物料、不看容差内的偏差。他们只看三类：影响已承诺客户交期的、长交期件的、有 MOQ / 批量跳变的。
- **优化**：把「逐条处理消息」优化成「按订单或客户成组处理」——一个客户订单缺 5 个件，就谈一次交期，而不是催 5 次料；把消息排序从物料号改成「金额 × 天数偏差」；把**反复出现的同一条消息**标记为"参数有问题"，去改参数，而不是每天重新处理一遍。
- **额外**：老手额外做——(a) **跑批前的数据健康度看板**（BOM 准确率、库存准确率、有多少条交期参数超过一年没更新、past due 数量），先修数据再看结果；(b) **参数治理**：定期把系统里的 lead time / MOQ / 安全库存与实际值比对（"供应商实际交期比系统里长两周"是最常见的隐形杀手）；(c) **量化神经质**：统计每次跑批产生多少条改期消息、其中多少条是上一轮刚处理过的——这个比例自己会告诉你时界和批量参数该不该调；(d) 跑批前先做 what-if，确认这轮上层变动会带来多大扰动再决定放不放行；(e) 保留一份"不归 MRP 管"的清单——关键长交期件走独立的协同流程，不靠自动消息。

#### 4.3 失败模式自检

- **崩点 1（最常见）**：库存 / BOM 数据不准，MRP 输出全是噪音。判别：计划员开始绕过系统"凭经验"下单。→ 先修数据（见工作流 10）。
- **崩点 2**：例外消息量超过人能处理的规模（一天几千条）。判别：消息积压、past due 越积越多。这是过滤规则没设，不是人手不够。
- **崩点 3**：交期参数是"祖传"的，从未和实际比对。判别：采购天天催料，货还是总晚。
- **崩点 4**：没有时界，销售可以随时改单。判别：同一张工单一周内被改期 3 次以上。
- **崩点 5**：只做单层齐套检查。判别：工单已经下达才发现下层缺料。
- **崩点 6**：安全库存被系统计入净需求，实际却被计划员手工"借用"掉。判别：账面有安全库存，现场却在缺料。

#### 4.4 近期变化（2024-2026）

- **从「每周跑一次」向「日跑 / 近实时重算 + 情景对比」迁移**：Kinaxis 的并发重算、SAP S/4HANA 的 pMRP（predictive MRP）都在这个方向。[T03-S003] [T03-S004]（vendor docs）
- **AI 落在例外消息的分诊（triage）而不是决策**：按预测影响排序、自动合并同源消息、给出建议动作，是 2024-2026 最扎实的落地点；让 AI 直接改计划仍属试点。
- **DDMRP 作为并行 / 替代路线继续扩散**：不用净需求驱动全链，而在解耦点用缓冲和净流量方程驱动，天然减少神经质（下层不再被上层需求波动直接打穿）。[T03-S014] [T03-S015]
- **多来源多交期建模**成为刚需：关税与断供让同一个件按来源不同的交期 / 成本做情景对比变成常规动作。
- `(Decay risk: medium)` —— MRP 的核心逻辑（毛需求 / 净需求 / 批量 / 倒排）1970 年代定型，几乎零衰减；例外处理的工具与 AI 分诊是快变部分。

### 工作流 5 — 瓶颈识别与 DBR 排产（TOC 五步聚焦）

TOC（Theory of Constraints，约束理论）由 Eliyahu Goldratt 在 1980 年代提出，核心主张是：任何系统的产出都被极少数约束决定，改善非约束不产生系统收益。TOCICO（TOC International Certification Organization）维护其 Body of Knowledge 并做认证。[T03-S020]

#### 5.1 入门 SOP

1. **先把「目标」和吞吐量口径讲清** —— 谁做：厂长 / 运营总监。输入：TOC 的三个衡量指标——Throughput（有效产出，指卖出去产生的钱，不是产出的件数）、Inventory / Investment、Operating Expense。产出：本轮改善的目标。这一步不做，团队一定跑去优化局部效率。
2. **识别约束（Identify）** —— 谁做：工业工程 + 生管。**这是新手最容易做错的一步**：
   - **不要**直接认定"设备利用率最高的那台就是瓶颈"。利用率高可能只是因为它批量大、换型多、或者在做返工——高利用率不等于高有效产出。
   - **看队列**：哪台设备前面永远堆着在制品 WIP，而它的下游在等活。这是现场最可靠的信号。
   - **看加班与催单**：哪个工序永远在加班、永远被催、永远是交期解释的理由。
   - **算负荷比**：把未来 4-8 周订单按工艺路线展开成各资源的负荷小时 ÷ 可用小时，比值最高且 >1 的是约束。
   - **别忘了约束可能不在车间**：可能是市场（订单不够）、某个供应商、某个审批环节，甚至是"全厂只有一个会调这台机的师傅"。
3. **最大化利用约束（Exploit）** —— 不花钱先榨干：
   - 约束不许停：吃饭轮班、班次交接不停机、预防性维护安排在非生产时段。
   - 约束不做废品：把检验挪到约束**之前**，绝不让约束去加工注定报废的料。
   - 约束不做不该它做的活：能外协、能用别的设备做的，全部挪走。
   - 排产优先级按 **Throughput per constraint-hour**（=(售价−变动成本) ÷ 占用约束的小时数）排，**不按毛利率排**。这两个排序经常给出完全相反的答案。
   - 在约束上做 SMED 换型改善——在约束上省下的换型时间直接等于全厂增加的产能。
4. **其余服从（Subordinate）—— DBR** —— 最难也最反直觉的一步：非约束资源**不要**追求 100% 利用率，它们唯一的使命是保证约束不断料。
   - **Drum（鼓）**：约束的排产计划就是全厂节拍。
   - **Buffer（缓冲）**：在约束前面放**时间缓冲**（"保证约束前永远有 X 小时的活"），不是数量缓冲；另外在发货前放一段出货缓冲。
   - **Rope（绳）**：投料时点 = 约束需要的时点 − 缓冲时间。前工序**不许**为了"保持忙碌"提前投料。
   - **缓冲管理**：把缓冲按消耗程度分绿 / 黄 / 红三区，进红区即触发动作。这是 DBR 的日常运行方式。
5. **提升约束（Elevate）** —— 开始花钱：加班、加人、买设备、外协、换更快工艺。**只有在第 3、4 步榨干之后才做**——太多工厂跳过 exploit 直接买设备，钱花了产出没变。
6. **回到第一步，别让惯性成为新约束（Inertia）** —— 约束一旦被打破就会转移。原来为旧约束定的排产规则、批量、KPI 全部必须重审，否则**规则本身会变成新的约束**。Goldratt 对第五步的原话是"如果前面的步骤打破了某个约束，回到第一步，但不要让惯性造成系统约束"。[T03-S020]

#### 5.2 资深路径

- **跳过**：老手跳过全厂产能建模。他们知道 80% 的工厂只有 1-2 个真约束，直接到现场看 WIP 堆在哪，十几分钟就能定位。也跳过对非约束工序的效率改善项目——那些收益是账面的。
- **优化**：把「定期找瓶颈」优化成「持续看缓冲穿透率」——不再周期性做产能分析，而是盯约束前缓冲进红区的比例；把优先级规则从毛利率优化成单位约束小时有效产出；在约束不稳定或频繁漂移的车间，把完整 DBR 简化成 **S-DBR（Simplified DBR）**——只管一个出货缓冲，不显式管理约束缓冲，实施成本低很多。[T03-S020]
- **额外**：老手额外做——(a) **区分真瓶颈与漂移瓶颈**：如果瓶颈每周都在换，真正的约束通常是**排产规则或投料策略本身**，不是任何一台设备；(b) 有意在非约束上留 15-30% 的**保护性产能**（业内经验值，非标准），因为非约束满负荷恰恰会让约束断料；(c) **改 KPI**：把非约束工序的考核从"设备利用率 / 产量"改成"是否按 rope 投料、是否让约束断过料"——不改 KPI，subordinate 这一步必然失败，这是 TOC 落地失败最常见的单一原因；(d) 把 TOC 和精益合用——用 VSM（工作流 6）找流动断点，用 TOC 决定先改哪一个。

#### 5.3 失败模式自检

- **崩点 1（最常见）**：把利用率最高的设备当瓶颈。判别：在"瓶颈"上砸了钱，全厂产出没变。→ 用队列位置和负荷比重新定位。
- **崩点 2**：Subordinate 推不下去，因为非约束工序还在被考核产量和利用率。判别：非约束在提前生产、WIP 在长。这是 KPI 问题，不是执行力问题。
- **崩点 3**：缓冲设成"多少件"而不是"多少小时"，一换品种就失效。
- **崩点 4**：约束其实在市场（订单不够）却在车间做改善。判别：设备闲着、交期很短、还在立效率项目。
- **崩点 5**：改善成功后不回第一步，旧规则继续跑。判别：约束早就转移了，排产还围着老设备转。
- **崩点 6**：把 TOC 当一次性项目而不是循环。判别：有一份两年前的"瓶颈分析报告"，此后再无更新。

#### 5.4 近期变化（2024-2026）

- **数据源变了**：MES / IIoT 让约束识别从"人工观察 + 月度产能分析"变成实时看 WIP 和设备状态，OEE 看板普及把定位门槛拉低了。但工具没有解决"用利用率找瓶颈"这个概念错误——**数据更多不等于诊断更对**。
- **有限产能排产求解器变强**：APS 的 finite capacity scheduling 让"显式 DBR"在多约束场景不那么必要；但 DBR 真正的价值在**投料控制和 KPI 对齐**，这部分求解器替代不了。
- **AI 用在瓶颈预测**（预测下周哪台会成为约束）而不是识别当前约束。
- **断链后的真实变化**：不少工厂的约束从设备移到了**物料和人**（缺料、缺技工），TOC 的分析对象必须跟着扩展到供应链和技能矩阵。
- `(Decay risk: low)` —— 五步聚焦与 DBR 逻辑从 1984 年《The Goal》至今没变。变化都在数据采集与排产工具层。

### 工作流 6 — 价值流图 VSM（现状图 → 未来图 → 改善计划）

VSM（Value Stream Mapping，价值流图）是精益里用来看「整条流」而不是「单个工序」的工具，由 Mike Rother 与 John Shook 在 1998 年的 *Learning to See* 中系统化，出版方是 Lean Enterprise Institute。[T03-S023] 它的两个产物是现状图和未来图，中间隔着一份改善计划。[T03-S022]

#### 6.1 入门 SOP

1. **选一个产品族（product family）** —— 谁做：VSM 负责人。输入：产品-工序矩阵（哪些产品走哪些工序、用哪些设备）。产出：一个明确定义的产品族。铁律：**不要给整个工厂画一张图**，画不完，也没法用。
2. **组队并指定 value stream manager** —— 谁做：厂长指定。产出：一个能对整条流负责的人（不是各工序主管组成的委员会）+ 跨职能小组（生产、计划、质量、物料、设备各 1 人）。没有这个人，图上跨部门的那一段永远没人改。
3. **从客户端往回走现场（gemba）** —— 谁做：全组一起走，不是派一个人去抄数。输入：一张 A3 纸、一支铅笔、一块秒表。产出：**手绘**现状图。
   - 为什么必须自己走：(a) 系统里的 cycle time 是标准工时，不是现场真实节拍；(b) 在制品堆在哪、堆了多少，只有现场能看到，而 WIP 数量正是算 lead time 的关键输入；(c) **信息流**（谁给谁下指令、用什么方式、多久一次、有没有人私下打电话插单）在任何系统里都查不到；(d)「一起走一遍」的真正产出是让全组看到同一个事实，图只是副产品。
   - 走法：**从发货端逆流而上**，不要顺流。顺流会不自觉地按"应该怎样"去看，逆流才会被"这批料为什么在这儿等着"逼问。
4. **采数据、填数据框** —— 每道工序记：`C/T`（cycle time，操作员完成一轮全部作业要素的时间）、`C/O`（changeover，换型时间）、`Uptime` 或 `D/T`（停机）、`%C/A`（percent complete and accurate，流到下一环节时一次做对的比例）、批量、操作人数、可用工时。工序之间记在制品数量。[T03-S022]
5. **画信息流** —— 客户订单怎么来、预测多久发一次、计划怎么下到各工序、供应商怎么收到指令、有没有插单通道。这半张图是新手最常漏掉的。
6. **画时间线（lead time ladder）** —— 下面一条线是增值时间（各工序 C/T 之和）；上面一条是非增值等待（各库存点数量 ÷ 客户日需求 = 天数）。产出：总交期 vs 增值时间的比值。离散制造这个比值常常在 1% 以下（业内估计，随行业差别很大）。
7. **识别浪费与流动断点** —— 输入：现状图 + 七大浪费（过量生产、等待、搬运、过度加工、库存、动作、不良）。判据：哪里在推（push）、哪里 WIP 最厚、哪里 `%C/A` 最低、哪道工序的 C/T 超过 takt time。
8. **算 takt time，画未来图** —— `takt = 可用工作时间 ÷ 该期客户需求量`。*Learning to See* 给的未来图标准提问：按 takt 生产吗？做成品超市还是直发？哪几道能连成连续流？哪里必须用拉动超市？在哪一点下计划（pacemaker / 定拍工序）？怎么均衡产品组合（heijunka）？每次放行多少量（pitch）？需要哪些配套改善（SMED、TPM、防错）？[T03-S023] [T03-S021]
9. **出价值流改善计划** —— 产出：按「环（loop）」切分的行动计划，每环写清目标、责任人、时间点、衡量指标，月度复盘。
10. **达成后重画** —— 未来图实现即成为新的现状图，滚动下一轮。

#### 6.2 资深路径

- **跳过**：老手跳过"把所有工序都画上"——只画对流动有影响的节点，把稳定且不影响交期的工序合并成一个框。也跳过精确到秒的测时：决策只看数量级差异，数量级对了就够。
- **优化**：把「画完再改」优化成「边画边动手」——现场看到明显浪费当场立整改，不等未来图；把未来图从"远期理想图"优化成"6-12 个月能真做到的图"（这正是 *Learning to See* 的原意，未来图是近期可达目标不是理想国）；把改善计划按环推进，一环一环，而不是二十项并行。
- **额外**：老手额外做——(a) 画**物料流 + 信息流 + 现金流**三条线（把付款条件和收款账期画进去，因为现金周转常常才是老板真正关心的东西）；(b) 数据框里额外记 `%C/A` 和**换型频次**，这两个直接决定批量能不能降；(c) 画未来图前先做**需求变异分析**——需求波动极大时，连续流是画得出做不到的；(d) 把 VSM 找到的断点交给 TOC 排序（哪个断点才是真约束），避免二十个改善点平均用力；(e) 画产品族矩阵时顺手看有没有可合并的族，产品族合并本身常常是最大的一笔改善。

#### 6.3 失败模式自检

- **崩点 1（最常见）**：在会议室里拿 ERP 报表画图。判别：图上数字全是整数、来自系统；到现场一问工人说"不是这样的"。
- **崩点 2**：范围太大（整厂或多个产品族画一张）。判别：图画了三周还没画完。
- **崩点 3**：只画物料流不画信息流。判别：从图上看不出计划是怎么下的、插单从哪进来。
- **崩点 4**：未来图画成一步到位的单件流。判别：改善计划里"需要新建产线 / 买新设备"占了多数条目。
- **崩点 5**：没有 value stream manager。判别：三个月后只有工序内部的改善做了，跨部门那段原地不动。
- **崩点 6**：画完挂墙上。判别：图上的日期超过 12 个月，且没有第二版。

#### 6.4 近期变化（2024-2026）

- **过程挖掘（process mining）做数字化 VSM**：从 ERP / MES 事件日志自动重建流程路径与等待时间，能替掉一部分手工采数。但它只看得到**系统里记录过的事件**——没被记录的等待、返工、来回搬运恰恰是浪费的大头，所以现场走查只能被补充，不能被替代。
- **实时看板取代静态快照**：MES / IIoT 数据让"当前状态"持续刷新，VSM 从一次性照片变成持续监控。
- **精益社区近年反复强调的一点**：太多价值流图只画了流程，没画**管理系统**（谁每天看什么数、异常怎么升级、谁负责），结果图很漂亮改善不落地。[T03-S029]
- AI 在这条流程里目前作用有限，集中在自动算 takt / lead time 和把现场记录转成结构化数据。
- `(Decay risk: low)` —— VSM 方法本身 1998 年定型至今没变；变的只是数据采集方式。

### 工作流 7 — 新品导入 NPI 与多级 BOM / ECN 工程变更管理

#### 7.1 入门 SOP

1. **门径立项** —— 谁做：项目经理。输入：产品需求、商业论证。产出：立项 + 跨职能团队（研发、工艺、采购、质量、计划）+ 从量产日 SOP（Start of Production）倒排的节点日历。汽车业对应的是 AIAG 的 APQP 五阶段；APQP 第 3 版（2024 年起被 GM、Stellantis、Ford 要求实施）新增了 sourcing、变更管理、APQP 项目指标、风险评估缓解计划和 gated management 的内容。[T03-S025] [T03-S030]
2. **建多级 BOM：EBOM → MBOM** —— 谁做：研发出 EBOM（工程 BOM，按功能结构组织），工艺 / 制造工程转成 MBOM（制造 BOM，按装配顺序组织，含辅料、损耗率、包装、虚拟层 phantom）。产出：每层含件号、版本、用量、单位、损耗率、替代料与合格清单（AVL / AML）。**这一步最容易出事的地方是 EBOM 到 MBOM 的转换没有系统联动，两套 BOM 各改各的。**
3. **长交期件识别与预投** —— 谁做：采购 + 计划。输入：BOM × 各件交期。产出：关键路径件清单（交期长于「设计冻结到 SOP 的剩余时间」的那些件）+ 预投决策：下多少、承担多少变更风险、**谁签字**。这是 NPI 里最贵的一个决策——投早了一变更就是呆料，投晚了赶不上 SOP。
4. **样件与验证** —— 谁做：质量 + 供应商。产出：EVT / DVT / PVT（工程 / 设计 / 生产验证）试产结论；汽车业对应 PPAP 包（见工作流 8）。
5. **试产与爬坡** —— 谁做：制造工程 + 生产。产出：工艺文件、控制计划（Control Plan）、良率与节拍数据、问题清单闭环。
6. **量产移交（SOP）** —— 产出：BOM 冻结版本、成本卡、正式计划参数（交期、批量、安全库存），并把物料从"项目采购"切换到常规 MRP 驱动。
7. **变更管理链条：ECR → CCB → ECO → ECN**
   - `ECR`（Engineering Change Request）：谁提、为什么（质量问题 / 降本 / 元器件停产 / 客户要求）。
   - `CCB`（Change Control Board）评审：技术可行性、成本、认证影响、**库存影响**、是否需要客户批准。
   - `ECO`（Engineering Change Order）：授权变更并定义生效方式。
   - `ECN`（Engineering Change Notice）：把变更通知给所有需要执行的人。业内很多公司把 ECO 与 ECN 合成一份文件，但在受监管行业它们是两条独立记录。
   - **生效点（effectivity）三种写法**：按日期（date effectivity）、按序列号 / 批次（serial / lot effectivity）、按**耗尽为止（use-up）**。use-up 生效日是"现有供应对着毛需求消耗到零的那天"——Oracle 的实现是算出库存归零日再加一个工作日，并且当 use-up 日期变化时计划过程会自动更新受影响件的生效日。[T03-S027]（vendor docs）
8. **变更后的呆料处置** —— 谁做：计划 + 财务 + 采购。产出：受影响库存清单（成品 / 半成品 / 在制 / 原材 / 在途）+ 每一堆的处置方式（用完 / 改制 rework / 退供应商 / 报废 / 向客户索赔）。**最常被漏掉的两块是：已下达但未到货的 PO，以及供应商替我方备的原材和在制。**

#### 7.2 资深路径

- **跳过**：老手跳过"每个变更都走完整 CCB"。他们按变更分级：Class I（影响形状-配合-功能 form-fit-function、安全、法规认证、客户图纸）必须走全流程且常需客户批准；Class II（文档修正、不影响互换性）走简化通道。**分级规则事先定死**，不是每次现场吵一遍。
- **优化**：把「先定生效日期」优化成「**先算 use-up 日期，再拿它去谈生效日**」——先让系统算清现有库存与在途要多久用完，再和研发 / 客户谈时间点，而不是先拍板日期再发现要报废一堆。把变更影响面分析从"人工翻 BOM"优化成"系统 **where-used 多级反查**"。
- **额外**：老手额外做——(a) 一份**变更影响清单模板**：受影响的 BOM、图纸、工艺、控制计划、检具、包装、标签、说明书、备件、售后件、认证文件、客户 PPAP——新手往往只改了 BOM；(b) **长交期件的变更冻结窗口**：SOP 前 N 周不许再改影响长交期件的设计，N 就取该件的交期；(c) 把变更成本（呆料 + 重新认证 + 停线）算出来放进 CCB 决策材料，让"顺手改一下"变得有价格；(d) **替代料前置**：设计阶段就把 AVL 做到两家以上，避免后期为换料再走一整轮变更；(e) 跟踪 **ECN 周期时间**（ECR 提出到现场生效的天数）作为流程健康指标；(f) 对合约制造（CM / EMS）场景，把生效点与对方的采购承诺窗口（liability window）对齐，否则呆料责任归属必然打架。

#### 7.3 失败模式自检

- **崩点 1（最常见）**：EBOM 与 MBOM 两套系统各改各的。判别：车间用的 BOM 版本和 PLM 里的对不上。
- **崩点 2**：长交期件预投没有明确签字人和风险额度。判别：出了呆料没人认账，事后才开会定责。
- **崩点 3**：生效点拍脑袋定"下周一"，没算库存耗尽。判别：生效当天冒出大批呆料，同时现场新旧件混用。
- **崩点 4**：只算了自家仓库，没算在途、没算供应商处的原材与在制。判别：变更后 1-2 个月才冒出索赔单。
- **崩点 5**：变更没通知售后 / 备件线。判别：售后发出去的备件装不上。
- **崩点 6**：ECN 积压。判别：ECR 到生效的平均天数在变长——这个数一升，CCB 已经变成瓶颈。
- **崩点 7**：没做 where-used 多级反查，改了一个通用件，殃及其他产品线。

#### 7.4 近期变化（2024-2026）

- **PLM-ERP 双向集成成为基本要求**：EBOM→MBOM 自动转换和多级 where-used 反查已是选型硬指标；云 PLM 让中小企业也拿得到这个能力。
- **AI 用于变更影响分析**：从历史 ECN 学"这类变更通常还要改哪些文件"，输出检查清单建议——是 2024-2026 落地比较扎实的一类应用。
- **被动变更激增**：芯片与元器件停产（EOL / PCN，Product Change Notification）触发的替代料变更在 2021-2024 成为 ECN 的主要来源之一，很多公司因此把"元器件生命周期监控"做成常设岗位而不是事件响应。
- **法规驱动的变更**：欧盟数字产品护照（DPP）、电池法规等把物料成分与来源信息挂进 BOM，扩大了每次变更的影响面。
- **AIAG APQP 第 3 版 + Control Plan 第 1 版**（GM / Stellantis 2024-09-01、Ford 2024-12-31 起要求）把变更管理和 gated management 写得更硬，汽车链上的 NPI 流程需要相应改造。[T03-S030]
- `(Decay risk: medium)` —— ECR/ECO/ECN 与 effectivity 的逻辑非常稳；工具集成度与法规驱动部分变化快。

### 工作流 8 — 供应商选择与开发（RFQ → 审厂 → APQP/PPAP → 量产 → 年降）

#### 8.1 入门 SOP

1. **先定这个品类的关系策略：Kraljic 矩阵** —— 谁做：采购经理 + 技术。输入：该品类对利润的影响（profit impact，通常用采购金额、对成本结构的占比、对产品性能的影响衡量）+ 供应风险（supply risk：合格供应商数量、技术壁垒、地缘、替代难度）。产出：四象限归位与对应策略。这个矩阵出自 Peter Kraljic 1983 年 *Harvard Business Review* 的 "Purchasing Must Become Supply Management"。[T03-S024]
   - **战略（strategic，高利润影响 + 高风险）**：长期伙伴、联合开发、双向信息共享、联合降本。**不在这里打价格战**。
   - **杠杆（leverage，高利润影响 + 低风险）**：多家竞标、集中量、频繁议价。招标和年降的主战场在这一格。
   - **瓶颈（bottleneck，低利润影响 + 高风险）**：保供优先——多年合同、安全库存、找替代方案，或者干脆推动设计改型把这个件去掉。
   - **一般（non-critical，低 + 低）**：流程效率优先——目录采购、打包外包、少花人力。
2. **RFI → RFQ** —— 谁做：采购。输入：技术规格 / 图纸、需求量与周期、质量要求、包装与物流要求。产出：**可比的**报价——要求把价格拆成材料 / 人工 / 制费 / 模具 / 物流 / 利润（should-cost 结构）。杠杆品类至少 3 家，其他至少 2 家。铁律：**不做成本拆解的总价对比等于没比**。
3. **审厂 / 现场评估** —— 谁做：SQE（供应商质量工程师）+ 采购 + 技术。输入：审核清单（质量体系 ISO 9001 / IATF 16949、产能与设备、过程控制、追溯性、财务健康、EHS 与劳工合规、信息安全）。产出：评分 + 不符合项清单 + 整改计划与关闭期限。
   - 现场看什么最有信息量：看他们**自己的不良品处理区**（有多少、放多久、怎么判定）、看设备点检记录、看一次真实换型、看他们**怎么管自己的供应商**。这些比会议室里的 PPT 有用得多。
4. **样件与 APQP / PPAP** —— 谁做：供应商主导，SQE 监督。
   - **APQP**（Advanced Product Quality Planning，先期产品质量策划）是上游的分阶段策划方法；**PPAP**（Production Part Approval Process，生产件批准程序）是 APQP 的产物——一整包文件、数据和实物零件，用来证明供应商的过程能稳定做出符合图纸要求的件。两者都由 AIAG 维护。[T03-S025] [T03-S028]
   - PPAP 的 **18 个要素**包括设计记录、FMEA、控制计划、MSA（测量系统分析）、SPC 过程能力研究、材料与性能试验报告、外观批准报告、样件、检具、以及 **PSW（Part Submission Warrant，零件提交保证书）**。
   - **提交等级 1-5**：Level 1 只交 PSW；Level 3 是最常见的默认（PSW + 样件 + 完整支持数据）；Level 5 是资料留在供应商现场供评审。**无论提交哪一级，18 个要素都必须完成并在供应商处留存。**[T03-S041] [T03-S042]
5. **小批量试产 / 安全启动** —— 产出：过程能力（Cpk / Ppk）、节拍、良率、包装验证、追溯验证。常见做法是量产前几批加严检验；AIAG Control Plan 第 1 版把 "Safe Launch" 正式写进了控制计划阶段。[T03-S030]
6. **量产与放量** —— 产出：正式框架协议，条款要覆盖价格、量、交期、库存与责任窗口（liability window）、变更条款、原材料涨价联动、**模具与工装归属**。
7. **年度绩效与年降谈判** —— 谁做：采购 + 质量 + 计划。输入：供应商记分卡（质量 PPM、OTIF / DIFOT、响应与配合、成本、技术贡献、EHS 与合规）。产出：等级评定 + 份额调整 + 年降。**年降必须有依据**——学习曲线、量的增长、联合改善（VA/VE）带来的实际成本下降、原材料指数联动——而不是"每年一律砍 3%"。

#### 8.2 资深路径

- **跳过**：老手跳过对 non-critical 品类做全套审厂和 PPAP，标准件、目录件只做资质核验加抽检。也跳过"每年对所有供应商现场审核一遍"，改成按风险与绩效分级（红档一年两次、绿档三年一次）。
- **优化**：把 RFQ 从"比总价"优化成"比 should-cost 拆解 + **总拥有成本 TCO**"（含关税、物流、MOQ 带来的库存、质量成本、账期的资金成本、切换成本）；把审厂从"填打分表"优化成"验证据链"——随机挑一个批次，能不能从收料一路追到出货；把年降从"砍价"优化成"**联合降本**"（改设计、改包装、改工艺、合并规格），因为纯砍价一定会被供应商用降质量偷回去。
- **额外**：老手额外做——(a) **有效的双源**：不是"名单上有第二家"，而是第二家做过认证、接过实际订单、随时能放量；(b) **tier-2 可视化**：至少对战略件穿透到二级供应商；(c) **供应商财务健康监测**（要求付款周期突然缩短、催款变频繁、核心人员流失，都是早期信号）；(d) **模具 / 工装归属与转移预案**——模具在谁手上，直接决定了换供应商的真实难度；(e) 给战略供应商做**联合业务计划**：把量的可见性给对方，换对方的产能与价格承诺，这才是 Kraljic 战略象限的真实做法；(f) **把审核发现和 PPAP 数据接进来料检验策略**（Cpk 高的免检、低的加严），让前期投入真的换回后期节省；(g) 把"谁能批准新供应商 / 谁能批准替代料"写成硬规则，堵住研发或销售为赶进度绕流程的口子。

#### 8.3 失败模式自检

- **崩点 1（最常见）**：按最低价选型，量产后用质量问题和加急运费把差价还回去。判别：新供应商第一年的质量成本 + 加急运费 > 当初省下的差价。
- **崩点 2**：审厂只审一天、只看展示线。判别：审核报告里没有不符合项，或全是"文件不齐"这类不痛不痒的项。
- **崩点 3**：PPAP 走形式（数据取自最好的一批）。判别：量产 Cpk 远低于 PPAP 报告里的数字。→ 过程能力研究必须来自量产工装、量产人员、量产节拍下的连续批次。
- **崩点 4**：Kraljic 里明明归为 bottleneck，却只认证了一家且没有库存缓冲。
- **崩点 5**：年降压过头，供应商悄悄换次级原材或转包。判别：PPM 缓慢上升、对方开始婉拒现场审核。
- **崩点 6**：记分卡权重全压在价格上。判别：得分最高的供应商恰恰是交期最差的那家。
- **崩点 7**：模具在供应商手里且合同没写归属。判别：真想换供应商时发现换不动。

#### 8.4 近期变化（2024-2026）

- **AIAG APQP 第 3 版 + Control Plan 第 1 版落地**：GM 与 Stellantis 自 2024-09-01、Ford 自 2024-12-31 起要求实施；新增 sourcing、变更管理、APQP 项目指标、风险评估缓解计划、gated management，并引入 Safe Launch。汽车链上的供应商开发流程需要相应改造。[T03-S030]
- **合规尽调进入审厂清单**：德国供应链尽职调查法 LkSG、欧盟 CSDDD 与强迫劳动产品禁令、美国 UFLPA，把审厂从质量维度扩展到人权、环境、可追溯。
- **关税与产地规则反复变动**（2024-2026），使"产地证明与关税归类"成为 RFQ 必问项；double-sourcing 从"两家供应商"升级为"两个国家 / 关税区"。
- **AI 落在辅助层**：供应商风险监测（新闻 / 财务 / 制裁名单持续扫描）、报价拆解与 should-cost 自动建模、审核报告结构化。定供应商的仍然是人。
- **中国制造业的具体变化**：越来越多外资客户要求"China + 1"，同一个件要在国内和东南亚 / 墨西哥各开发一次，审厂与 PPAP 做两遍（业内观察）。
- `(Decay risk: medium)` —— Kraljic 与 APQP/PPAP 的骨架很稳；合规与关税这一层高度易变。

### 工作流 9 — 断料应急与交期承诺（ATP / CTP）

#### 9.1 入门 SOP

1. **先确认缺口是真的** —— 谁做：计划员。输入：MRP 缺料清单、库存记录、在途、替代料清单。产出：确认后的缺口（缺多少、影响哪些订单、缺到哪天）。**先排除"数据假缺料"**：库存不准、在途没维护、替代料没挂在 BOM 上——这三样占了很大比例。
2. **先做不花钱的补救** —— 谁做：计划 + 采购。按顺序试：AVL 里的第二家 / 可互换件 → 拆解已有半成品或成品（cannibalize，需质量与财务批准）→ 从其他工厂或仓库调拨 → 请供应商把已有 PO 提前（pull-in）→ 现货市场（对电子元器件要有假货检测预案）。
3. **再做花钱的补救** —— 空运加急、加急费、代理商溢价、改用高一档规格的件。每一项都要算清"保住的订单价值 vs 花掉的钱"，并且要有人签字。
4. **定分配规则（allocation）** —— 谁做：S&OP 决策或专设的分配会。三类常见规则：
   - **公平分摊（fair share）**：按各渠道 / 客户的需求占比或历史采购比例分。法律上，被不可预见事件逼着分配时通常被期望做到"fair and reasonable"，按上一年度采购比例分配或按下单先后履约，都属于被认可的做法。[T03-S035]
   - **优先级（prioritization）**：按客户等级、合同罚则、战略重要性、毛利、断货后果排序。[T03-S038] [T03-S039]
   - **优化（optimization）**：用线性 / 混合整数规划，在产能、交期、SLA 约束下最大化利润或服务水平。
   - **铁律：分配规则必须事先写下来**，不能等缺货当天现讨论——否则一定演变成谁嗓门大谁拿货，而且有法律风险。
5. **算可承诺量 ATP / CTP** —— 谁做：客服 + 计划。
   - **ATP（Available to Promise，可承诺量）**＝ 现有库存 + 已计划入库 − 已承诺给客户的量，按时间桶逐期累计。它**假设产能无限**，只看物料与库存侧的供应。
   - **CTP（Capable to Promise，可承诺能力）**：ATP 不够时，进一步模拟"现在开一张工单、用可用产能和可用组件，最早什么时候能交"。SAP 的 CTP 是在 Global ATP 里集成 PP/DS，做多层组件与产能检查后给出可靠交期。[T03-S026]（vendor docs）
   - 还有一层 **product allocation check（配额检查）**：缺货期给每个客户 / 渠道设配额，订单先撞配额再撞库存；在多 BOM 层、多有限产能资源的复杂场景，SAP 建议用"配额检查 + 有限排产"替代完整 CTP。[T03-S026]（vendor docs）
6. **决定要不要拆单** —— 判据三条：客户能不能用部分数量（有的客户装配要齐套，拆单等于零）；拆单的额外物流成本；**拆单对 OTIF 的影响**。注意 **OTIF 是"准时且足量"，任何一项不满足整单即算失败**——所以在有 OTIF 罚则的零售客户那里拆单常常不划算，在工业客户那里常常划算。[T03-S036]
7. **跟客户沟通** —— 谁做：销售 + 计划**一起**去，不能只让销售单独扛。产出：一次说清五件事——现状、根因、新的承诺日期、这个日期的可信度、补偿方案、以及下次更新的时间点。铁律：**宁可一次给一个稍晚但守得住的日期，也不要连续三次给守不住的日期**，交付信誉的损失是复利的。
8. **复盘与防再发** —— 产出：根因（预测偏差？供应商产能？质量批退？系统参数错？）+ 对应的参数或流程修正，回灌到工作流 2 / 3 / 4。

#### 9.2 资深路径

- **跳过**：老手跳过对小额、易得件走完整应急流程——直接买贵的现货了事，因为应急流程本身有成本。也跳过"每个缺料都开会"，只对影响已承诺交期的开。
- **优化**：把「缺料后再排优先级」优化成「**预先定好客户分级与分配规则**」，缺货当天只执行不辩论；把 ATP 从"看仓库有没有"优化成"看整个时间轴上的净可用量"，并且**把已承诺量真正扣减掉**（很多公司 ATP 不准的唯一原因就是没扣已承诺）；把交期承诺从"凭经验拍"优化成"按实际产能负荷算"——CTP 的本质是把承诺建立在能力上而不是乐观上。
- **额外**：老手额外做——(a) **缺料预警而不是缺料响应**：盯长交期件的供应商确认交期变化、盯替代料的可得性，在真缺之前 4-8 周就动手；(b) 保留**物料与产能的应急缓冲**，并明确谁有权动用；(c) **报价时就区分交期类型**：有货报现货交期、无货报能力交期，不要用同一个数字；(d) 把 **Little's Law 和变异缓冲的逻辑用在交期承诺上**——`交期 = WIP ÷ 产出率`，且在高利用率下排队时间会非线性暴涨，所以承诺交期必须随负荷动态浮动而不是常年报一个固定天数。[T03-S033] [T03-S034] 再加一条 Factory Physics 的结论：**生产系统里的变异只能被库存、产能、时间三者之一（或组合）吸收**——不肯留库存也不肯留产能，就必须接受长交期，这是可以拿去和销售讲的物理约束而不是态度问题。[T03-S037]
- **额外**：老手会准备一份"给客户的话术 + 数据包"模板，让销售不必在客户面前临场编。

#### 9.3 失败模式自检

- **崩点 1（最常见）**：假缺料。判别：一线经常"再找一找就找到了"。这是库存准确率问题，去看工作流 10。
- **崩点 2**：分配规则临时定。判别：分配会开成吵架会；同一周内同一批货出现两种分法。
- **崩点 3**：ATP 数字不可信（没扣已承诺、没算在途、按整月桶不按日）。判别：系统说有货，实际发不出。
- **崩点 4**：承诺日期是销售自己拍的，计划不知情。判别：订单上的要求日与系统可交日长期对不上。
- **崩点 5**：连续改期。判别：同一张订单改期 3 次以上。此时正确动作是给一个带足缓冲的日期并守住，而不是继续乐观。
- **崩点 6**：只顾着救最吵的客户，把长期战略客户的货挪走了。
- **崩点 7**：应急变常态。判别：加急运费占物流费的比例连续几个月上升——这时要修的是计划，不是物流。

#### 9.4 近期变化（2024-2026）

- **控制塔（control tower）与在途可视化成熟**：供应商发货、在途、清关、入库的事件流打通，缺料预警从"到货那天才知道"提前到"起运就知道"。
- **AI 的落地点是"影响推演 + 方案生成"**：给定一个缺料，自动推演影响哪些订单、生成几套补救方案并按价值排序——2024-2026 已在主流 APS 里常规化。[T03-S003]（vendor docs）
- **元器件短缺周期化**：2021-2023 芯片荒之后，很多公司常设"元器件生命周期与库存监控"岗位；现货市场的假货风险管理（第三方检测）成为标准动作。
- **航线中断成为常规扰动**：2024 年红海绕行普遍拉长亚欧海运时间，交期承诺开始按航线情景给**区间**而不是单点。
- `(Decay risk: medium)` —— ATP/CTP 逻辑与分配原则很稳；可视化与 AI 推演这一层变化快。

### 工作流 10 — 循环盘点与库存准确率

APICS 词典对 cycle counting 的定义是「按周期性排程而非一年一次地清点库存的准确性审计技术」。[T03-S040]

#### 10.1 入门 SOP

1. **先定义准确率口径** —— 谁做：仓储 + 财务 + 计划。产出：写死的口径。关键点：**按行（SKU × 库位）算，不按金额算**——`准确率 = 容差内相符的记录条数 ÷ 抽查记录条数`。金额口径会让几个大件把一堆小件的错误盖掉。容差按物料分级（高值件 0 容差；散装 / 称重件可给 ±1-2%）。
2. **定分层与频次** —— 谁做：计划。输入：ABC 分类 + **动碰次数（hit frequency）**。产出：盘点日历。常见做法是 A 类月度或季度、B 类半年、C 类一年（业内常用做法，各家不同）。更好的做法是按动碰频次而不只按金额分——动得越多越容易错。
3. **定盘点方式** —— 产出：作业 SOP。三个要点：**盲盘**（不把系统数量给盘点人）、在无作业时段或冻结该库位、**按库位盘而不是按物料盘**（按物料盘会漏掉"放错库位"这一类错误）。
4. **执行与记录** —— 谁做：仓管，且最好不是日常负责该区域的人。产出：实盘数 + 差异清单。
5. **复盘与调账** —— 差异超过阈值的先复盘一次再调账；调账必须有审批和**原因码**。
6. **根因追查（这一步才是循环盘点真正的价值）** —— 谁做：仓储主管 + 计划。产出：根因分类与纠正措施。常见根因：收货数量错或未及时入账、发货扫错、单位换算错（箱 vs 个）、退货未入账、生产领料与实际用量不符（含损耗率参数设错）、放错库位、拆包散件没记、盗损、WMS 与 ERP 接口失败。
7. **出准确率报表并跟趋势** —— 产出：按仓库 / 区域 / 物料类别的准确率趋势 + 根因分布。**趋势和根因分布比某一次的数字更有用。**
8. **反馈到参数** —— 差异反复出现的物料，回头检查它的损耗率、计量单位、批次规则是不是设错了。

**为什么年度大盘点不如循环盘点：**

- 年度盘点买到的是"12 月 31 日那天准"，第二天就开始失准；而 MRP 每天都在用这个数。循环盘点买到的是"全年持续准"。
- 年度盘点要停产、停收发货，直接成本高。
- 年度盘点**只能调账，追不了根因**——几千条差异当天查不完；循环盘点每次差异只有几十条，能追到根因并修流程。**这才是循环盘点的真正价值，不是省时间。**
- 年度盘点的差异会被正负相抵掩盖：多的和少的一冲销，总金额看着还行，实际每一行都不准。

**准确率门槛怎么看（数字要标出处）：**

- 常被引用的两个数：一是业界（含 APICS 语境）把 SKU 层 **95%** 当作"世界级"门槛；二是"MRP 需要 **98%** 库存准确率"这条老经验法则。这两个都是**经验值不是标准**，而且强烈依赖容差定义——用 ±5% 容差算出的 98% 和 0 容差算出的 98% 完全不是一回事。[T03-S031] [T03-S032]
- 更实用的读法：**不要追某个数字，追"准确率趋势向上 + 根因分布在收敛"**。有观点直接指出，MRP 在低于 98% 时一样能跑，只是准确率越低，你要么牺牲可得性，要么用更多库存去补——这个取舍关系比门槛数字有用。[T03-S032]

#### 10.2 资深路径

- **跳过**：老手跳过对呆滞、低值、不影响生产的物料做高频盘点。也跳过"盘完立刻调账"——差异大的先查再调。
- **优化**：把频次从"按 ABC"优化成"**按风险 × 动碰次数**"（一年只动两次的 A 类，比天天动的 C 类更不容易错）；把"定期盘"优化成"**事件触发盘**"——领料时发现短少、拣货时数量对不上、库位空了但系统有数，当场触发一次点数（很多 WMS 叫 opportunity counting / zero-count）；把差异报告从"列一张清单"优化成"按根因归类并指派责任人"。
- **额外**：老手额外做——(a) **把准确率拆到人和班次**，找出误差是在哪个环节被制造出来的；(b) **先修流程再加盘点**：如果收货入账本身就延迟 4 小时，盘再多也只是不停地调账；(c) **把在制品和线边仓纳入盘点**——这是最常被忽略、差异也最大的两块；(d) **把损耗率与实际用量的偏差当成独立指标跟踪**，因为生产领料差异常常被误当成盘点误差；(e) 高值件做**双人复核 + 批次 / 序列号追溯**，不是只数数量；(f) 拒绝"为了过审计而调账"，每一次调账都留原因码，否则一年后没人知道钱丢在哪。

#### 10.3 失败模式自检

- **崩点 1（最常见）**：盘点人就是日常管这个区的人，而且知道系统数量。判别：差异率异常低，但生产老是缺料。→ 盲盘 + 换人。
- **崩点 2**：只调账不追根因。判别：同一个物料每个季度都出差异。
- **崩点 3**：按金额算准确率。判别：准确率 99%，现场天天缺件。
- **崩点 4**：容差定得太松。判别：准确率很高，MRP 却总算错。
- **崩点 5**：盘点期间还在收发货。判别：差异总是集中在盘点当天的进出货上——那不是差异，是时间差。
- **崩点 6**：只盘成品仓，不盘线边、在制、外协在库、退货区。判别：账实差异集中在这些"灰区"。
- **崩点 7**：盘点变成 KPI 游戏（先看系统数再"盘"）。判别：准确率常年 99.5% 且几乎没有波动——真实数据不会这么平。

#### 10.4 近期变化（2024-2026）

- **RFID 与视觉盘点扩散**：服装、零售、高值制造已能整箱 / 整区秒读，把盘点从"事件"变成"持续状态"；对小件、金属与液体环境仍有物理局限。
- **盘点无人机 / 机器人**在大型高位货架仓库开始规模化，把高位盘点的安全与人力成本问题解掉。
- **opportunity counting（作业触发盘点）成为 WMS 标配**，把盘点嵌进拣货动作本身，不再另外排班。
- **AI 用在差异预测**：预测哪些库位 / 物料下周最可能出差异，把盘点资源投过去——比固定周期更省，是 2024-2026 一个真实的增量。
- `(Decay risk: medium)` —— 循环盘点方法论极稳（可追到 1960 年代的 APICS 库存记录准确性文献）；采集技术（RFID、视觉、机器人）是快变部分。
